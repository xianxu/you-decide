# Substrate

The data the algorithm operates on. All shared substrate lives at the repo root (committed); user-private deliberation lives in the user's brain (encrypted, not in this repo).

## Public substrate (this repo)

### `candidates/<year>/<state>/<office>/<slug>.md`

Genesis-tracked candidate profile. Every claim has an inline source URL. Sections: bio, positions, controversies, source-tier annotations.

Generated by research subagents at Stage 1 of [[SKILL]] when the candidate first appears on a ballot the algorithm processes. Refreshed when stale (per the sub-skill's rules) or when an issue specifies a re-research.

### `controversies/<year>/<state>.md`

Cycle's controversy map per state. Each entry has a `Survey-ready stance:` line so [[bootstrap-survey]] (the `progressive` design) and [[SKILL]] Stage 2 can both compose questions from it directly.

Entries also carry candidate-side summaries (A/B/middle/outlier framings) so the survey can present canned options.

### `elections/<year>/<YYYY-MM-DD>-<state>-<scope>.md`

**Election-day-keyed ballot manifest**, not per-jurisdiction. CA has multiple election days per year (primary, general, special), and a single date's ballot covers many jurisdictions; date is the natural key.

Includes: voting system per race (top-2, ranked-choice, plurality), filing windows, key dates. `pending` entries are fine when filing hasn't closed.

### `sources/<US|state>.md`

Authoritative source registry. Tiers:

| Tier | Examples | Use |
|---|---|---|
| **A** Primary / official | Secretary of State, official campaign sites, court filings | Decisive — citations for hard claims |
| **B** Authoritative secondary | Major regional news (CalMatters, AP, KQED, LA Times for CA) | Standard reporting |
| **C** Lower-trust | Blogs, partisan sites, social media | Avoid for decisive claims; flag if used |

Composed at runtime: `sources/US.md` always loaded; `sources/<state>.md` loaded for the state being processed. Sub-jurisdiction lists (county, city) added inline in those files as needed.

### `reviews/<year>/<date>-<batch>.md`

Review session output — see [review](review.md).

## Private substrate (user's brain, not this repo)

Path inside brain: `data/life/politics/who-to-vote-for/`.

- `philosophy-<user>.md` — the user's political philosophy file. Source of truth for what the user believes. Grows organically across cycles via [[SKILL]] Stage 3 disambiguation + Stage 4 disagreement-loop corrections.
- `calibration-skills/*.md` — user-specific corrections that don't generalize (the shared ones live in `you-decide/calibration-skills/` in this repo).
- `<year>/<state>/<race>/<slug>-read.md` — per-candidate axis reads. Pure function of (philosophy, calibration skills, candidate profile); cached and reused.
- `<year>/<state>/<race>/vote.md` — final deliberation per race: conscience vote, strategic vote, scenarios, parked questions, active calibration skills.

## Per-file frontmatter contract

Every markdown file in the **public substrate** (and the skill bundle itself) carries this frontmatter so the review pipeline can be greppable. Documented in [review](review.md):

```yaml
---
generated-by: <claude | gemini | gpt-4 | human>
generated-on: <YYYY-MM-DD>
review: <not-done | passed | failed | in-progress>
reviewed-by: <agent stack used for review>   # set when review != not-done
reviewed-on: <YYYY-MM-DD>                     # set when review != not-done
review-ref: reviews/<year>/<date>-<batch>.md  # link to the session
---
```

`scripts/audit-review.sh` greps for `review: not-done` and `review:` omissions to surface unreviewed files. See [review](review.md).

## Why split public / private

- **Shared substrate is reusable** — every user benefits from one well-researched candidate profile + one well-mapped cycle controversy file. Sharing it amortizes the AI research cost.
- **Deliberation is personal** — `philosophy-<user>.md` and `vote.md` contain identifying preferences. Stays in the user's encrypted brain, never the public repo.
- **Privacy boundary is at the directory level** — not at the field level inside a file. Makes the rule simple: "if it's in `who-to-vote-for/`, it's private; if it's in this repo, it's shareable."
